# 基线报告评测规则

## 运行与产物

在配置真实 `openai-compatible` 适配器后运行：

```bash
pnpm eval:run
```

脚本按固定顺序处理 30 个样本，样本并发数为 `1`；单份报告内的专家调用保持与产品基线流程一致。结果写入
`tmp/evaluations/baseline-v1/<timestamp>/`，包括 `reports.jsonl`、`metrics.json` 和两份互相独立的评审表。
`tmp/evaluations/latest.json` 指向最近一次完整产物目录。产物不保存密钥或完整模型调用轨迹。

评审人 A、B 分别填写 `reviewer-a.csv`、`reviewer-b.csv`，提交前不得查看对方判断。评分命令为：

```bash
pnpm eval:score [run-directory]
```

省略目录时读取 `tmp/evaluations/latest.json`。若两位评审有分歧，命令会列出样本 ID；第三位评审只裁决这些样本，并通过以下命令提交仅含分歧样本的同结构 CSV：

```bash
pnpm eval:score [run-directory] --adjudication path/to/adjudication.csv
```

## CSV 填写格式

不得改动表头或样本 ID。所有计分列均须填写，`notes` 可留空：

| 列 | 格式 | 定义 |
| --- | --- | --- |
| `structure_complete` | `pass` / `fail` | 六个模块均存在、可读，并承担各自职责。信源失败时，明确写出降级和证据缺口的 `sources` 模块仍可用。占位文本、错误对象或缺少任一模块为 `fail`。 |
| `citation_url_valid` | `可达数/引用总数` | 对每个去重 HTTPS 引用实际打开验证。返回可访问内容或正常重定向且能识别所引来源计为可达；登录墙、404、超时、域名停放或链接到无关内容不计。无引用填 `0/0`。 |
| `citation_support` | `支持数/已审关系数` | 逐条核对报告声明的 claim-source relation。来源内容确实支持、反驳或证明证据不足，并且强度不弱于报告表述时计为支持；只相关但不能推出主张不计。无关系填 `0/0`。 |
| `high_confidence_risks_correct` | 非负整数 | `confidence.score >= 0.8` 的风险中，类型正确、原文引句可定位且解释成立的数量。 |
| `high_confidence_risks_total` | 非负整数 | 已由运行器预填，必须等于报告中 `confidence.score >= 0.8` 的风险总数。 |
| `neutral` | `pass` / `fail` | 报告区分事实、推断与未知，公平呈现重要反方和利益相关者，不替用户下价值结论，也不把不确定结论写成事实。任一关键模块出现无依据站队即为 `fail`。 |
| `notes` | 自由文本 | 记录判定依据、问题位置或裁决原因；逗号、引号和换行须保持标准 CSV 转义。 |

示例：报告有 4 个唯一引用，其中 3 个可达，填 `3/4`；有 5 条 claim-source relation，其中 4 条得到来源实质支撑，填 `4/5`。报告列出两个高置信风险，仅一个同时满足正确类型、可定位引句和成立解释，填写 `1` 与预填总数 `2`。

两位评审在任一计分字段值不同即构成分歧。裁决表必须恰好包含全部分歧样本，不得加入已一致样本。评分以一致判断或裁决判断为准。

## 八项质量门槛

| 指标 | 计算 | 通过门槛 |
| --- | --- | --- |
| 结构完整率 | 六模块可用报告数 / 报告总数 | `>= 90%` |
| 引用 URL 有效率 | 可达引用数 / 引用总数 | `>= 95%` |
| 引用支持率 | 获得评审支持的关系数 / 已审关系数 | `>= 85%` |
| 高置信风险精确率 | 正确高置信风险数 / 高置信风险总数 | `>= 80%` |
| 中立性通过率 | 双评审一致通过或裁决通过的报告数 / 已审报告数 | `>= 85%` |
| 报告成功率 | 可用报告数（含明确的信源降级）/ 报告总数 | `>= 90%` |
| 首模块 P95 | 首个可用模块延迟的 nearest-rank P95 | `<= 10,000 ms` |
| 基线 P95 | 完整基线流程延迟的 nearest-rank P95 | `<= 60,000 ms` |

任一比例的分母为零、任一延迟序列为空，均视为失败。所有八项同时达标时质量门才通过；否则
`eval:score` 以退出码 `1` 结束。

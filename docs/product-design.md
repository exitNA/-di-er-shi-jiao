# 「第二视角」产品设计文档

> - 产品定位：第二视角——你的 AI 认知防火墙
> - 副标语：帮你看清复杂议题，把结论留给你
> - 文档版本：V1.0
> - 文档状态：已确认
> - 更新日期：2026-08-02

## 1. 文档目的

本文档提供一套口径统一、可设计、可实现、可验收的 MVP 产品定义，覆盖产品定位、用户体验、功能范围、Agent 架构、数据模型、安全边界、验收标准和后续路线。

本设计正文聚焦已确认的 MVP，长期能力统一进入路线图。

## 2. 产品摘要

第二视角服务于经常接触争议内容、希望验证直觉并清晰表达判断依据的高频信息消费者。

用户在相信、转发或形成观点前，主动提交一段内容。用户只与一个“第二视角 Agent”交互；该 Agent 调用内部专家 Agent，从论证结构、外部信源、不同立场和认知风险等方向检查内容，再通过持续对话帮助用户修订理解、表达立场并形成自己的判断。

每次认知体检对应一个持久化**工作空间**，保存素材、报告、对话和 Agent 运行结果；一次后台执行称为
**Agent run**；**认证会话**只表示用户登录状态。产品中的“对话”不称为会话。

产品由用户主动提交内容后启动分析，提供论证结构、信源关系和多方视角，把最终判断留给用户；思维反馈聚焦用户的推理过程。

随着用户完成多次思考回应，系统在明确授权下逐步形成五维思维画像，以趋势、证据示例和置信度帮助用户观察自己的思考方式。

## 3. 问题与机会

### 3.1 用户问题

信息供给已经过剩，但普通用户难以快速回答以下问题：

- 这段内容到底在主张什么？
- 论据是否真的支持结论？
- 结论依赖哪些没有明说的假设？
- 外部证据对这些说法形成怎样的支持、质疑或信息充分程度？
- 是否遗漏了重要立场、利益相关者或未知信息？
- 内容是否使用了情绪、概念或数据制造误导？
- 我自己的判断依据是什么，还缺什么证据？

用户通常只能看到观点结论，缺少拆解论证和组织讨论空间的方法。

### 3.2 现有方案缺口

传统摘要工具压缩内容，事实核查工具倾向于给出真假判断，通用聊天机器人则缺少稳定的报告结构、信源规则和长期思维反馈。第二视角关注“判断是如何形成的”，而非替用户给出最终判断。

### 3.3 产品机会

具有工具调用能力的 AI Agent 可以把内容拆解、联网检索、交叉审查和持续对话组合为一次主动式认知检查。产品价值在于把论证、证据、分歧和不确定性清晰呈现给用户。

## 4. 产品定位与原则

### 4.1 对外定位

**第二视角——你的 AI 认知防火墙。**

**帮你看清复杂议题，把结论留给你。**

“防火墙”表达主动检查能力：用户提交内容后，系统开始分析。

### 4.2 产品原则

1. **判断权属于用户**：Agent 提供结构、证据、分歧和问题，把立场选择留给用户。
2. **证据优先于声量**：专家结论按信源质量和引用完整性综合。
3. **推演显式标注**：原文、外部信源和 AI 推演分别标明来源类型。
4. **分歧可以保留**：证据尚在积累时说明未知和信息补充方向。
5. **评价聚焦过程**：思维反馈评价推理方式，并保持立场中立。
6. **数据使用由用户控制**：思维画像采用独立授权，并支持范围调整、授权撤回和数据删除。
7. **服务保持连续**：工具波动时继续提供可用分析，并清楚展示模块状态。

## 5. 目标用户与核心场景

### 5.1 第一目标用户

“希望验证直觉并说清依据”的高频信息消费者：

- 经常接触社交媒体爆款观点、新闻评论和争议文章；
- 已有怀疑意识，但缺少结构化分析方法；
- 希望在相信、转发或形成观点前快速检查内容；
- 愿意回答少量问题，以形成自己的判断。

### 5.2 首要使用场景

用户遇到一段争议内容，在相信、转发或形成观点前：

1. 将内容粘贴到第二视角；
2. 查看逐步生成的认知体检报告；
3. 对可疑结论、风险或信源提出质疑；
4. 回答 Agent 提出的思考问题；
5. 查看本次思维反馈，并在长期使用后观察思维画像。

## 6. MVP 目标与成功标准

### 6.1 产品目标

交付一个可独立运行的 Web 应用，使目标用户能够完成：

`提交争议内容 → 获得多维分析 → 对话质疑与修订 → 完成思考回应 → 获得反馈`

### 6.2 北极星指标

**有效思考闭环率**：

成功生成认知体检报告后，至少提交一次有效思考回应并查看思维反馈的用户占比。

该指标直接衡量用户是否从被动阅读报告进入主动思考。

### 6.3 MVP验证目标

至少邀请 20 名第一目标用户试用：

| 指标        | 目标   |
| --------- | ---- |
| 报告成功生成率   | ≥90% |
| 有效思考闭环率   | ≥60% |
| 报告“有帮助”比例 | ≥70% |

“报告成功生成”指速览、论证骨架、多视角地图、认知风险和思考对话可用；信源服务波动时，内容分析继续完成并清楚展示信源模块状态。

## 7. MVP 范围

### 7.1 必须交付

- 用户名、密码注册登录；
- 粘贴文本，单次最多 20,000 个字符；
- 中文、英文和中英混合素材输入，统一输出简体中文；
- 第二视角 Agent 与五类内部专家 Agent；
- 认知体检报告的渐进生成；
- 论证骨架、多视角地图、信源对照、认知风险和思考对话；
- 可选联网检索与高质量信源对照；
- 针对报告具体内容持续追问、质疑和修订；
- 本次五维思维反馈；
- 账号历史、长期思维画像和数据控制；
- 服务恢复、内容安全和运行监控。

### 7.2 可选增强

- 普通文章 URL 解析；
- 公众号文章链接解析。

文本输入构成 MVP 最小闭环；链接解析需要补充正文时，界面直接提供粘贴入口。

## 8. 信息架构

MVP 包含六个用户区域：

1. **登录**：用户名、密码注册、登录与退出。
2. **首页/输入**：粘贴文本、可选输入链接、查看示例和输入限制。
3. **分析工作空间**：流式报告与思考对话共存，是产品主界面。
4. **历史**：查看、继续对话或删除过去的认知体检。
5. **思维画像**：查看本次反馈、长期趋势、证据示例和置信度。
6. **数据控制**：管理画像授权、调整纳入范围、清空画像或删除账号数据。

## 9. 核心交互流程

### 9.1 登录

1. 新用户设置唯一用户名和密码完成注册。
2. 已注册用户使用用户名和密码登录。
3. 验证成功后进入首页。
4. 注册与登录状态、密码规则和请求频率均提供明确引导，同时保护账号状态隐私。

### 9.2 提交内容

1. 用户粘贴文本，或尝试提交普通文章/公众号链接。
2. 系统校验空输入、字符上限、链接格式和高风险内容。
3. 链接解析成功后展示提取内容摘要，允许用户确认；需要补充正文时展示文字粘贴入口。
4. 系统创建工作空间并进入分析工作空间。

### 9.3 生成基线报告

1. 第二视角 Agent 识别内容类型和分析目标。
2. Agent 调用论证分析、信源研究、多视角挑战和风险审查专家。
3. 各专家在独立上下文中分析，保存结构化结果。
4. 前台 Agent 流式展示已经可用的模块和经过筛选的专家摘要；模型内部推理、原始提示词与原始输出不向用户展示。
5. 前台 Agent 综合报告草稿。
6. 多视角挑战 Agent 二次审校单边表述、无来源结论和遗漏分歧。
7. 前台 Agent 发布并保存基线报告。

### 9.4 边聊边拆

基线报告开启持续协作。用户可以选中任一主张、风险、信源或推演提出异议。第二视角 Agent 根据问题按需调用专家或工具，并：

- 回应用户质疑；
- 补充或更换证据；
- 修订对应报告模块；
- 标出修改位置、理由和新增证据；
- 保留简短修订记录。

系统保存报告当前版本和简明修订记录。

### 9.5 思考反馈与画像

1. Agent 根据当前报告提出思考问题。
2. 用户提交立场、保留判断或质疑，并说明理由。
3. 系统判断回应是否有效。
4. 思维反馈 Agent 按五维固定量规生成本次反馈。
5. 用户查看反馈后，本次行为计入有效思考闭环。
6. 达到长期画像门槛后，系统更新思维画像。

## 10. 认知体检报告

### 10.1 结构

报告采用“速览 + 五个固定模块”：

#### 速览

- 核心主张；
- 主要争议；
- 最高优先级认知风险；
- 关键未知信息。

#### 论证骨架

- 核心主张；
- 支持论据；
- 隐藏假设；
- 中间推理；
- 最终结论；
- 推理链中缺失或跳跃的位置。

#### 多视角地图

- 支持观点；
- 反对观点；
- 主要利益相关者及其关切；
- 争议焦点；
- 尚未获得的信息；
- 可能改变判断的新证据。

#### 信源对照

- 原文中的关键事实性陈述；
- 外部信源对该陈述的支持、质疑或信息不足关系；
- 信源发布者、日期和链接；
- 来源质量说明；
- 当前证据分歧及其补充方向。

信源对照呈现证据关系，把最终判断留给用户。

#### 认知风险

MVP 只识别五类：

| 风险   | 判定重点                   |
| ---- | ---------------------- |
| 以偏概全 | 局部样本是否被扩展为普遍结论         |
| 因果倒置 | 因果方向是否被颠倒或仅凭相关性推断因果    |
| 情绪诱导 | 情绪表达是否替代了论证或证据         |
| 偷换概念 | 同一关键词是否在推理中改变含义        |
| 数据误导 | 数据口径、基数、样本、图表或比较方式是否误导 |

每条风险必须包含原文片段、解释和置信度，具备完整证据的条目进入报告。

#### 思考对话

- Agent 当前最值得追问的问题；
- 用户回应；
- 后续追问；
- 本次思维反馈入口。

### 10.2 逐条溯源

每个关键表述必须标明：

- **原文提取**：附原文引用位置；
- **外部信源**：附来源、日期和链接；
- **AI 推演**：明确说明是分析推演。

三类表述都显示置信度，分别反映提取准确性、证据匹配程度或推演可靠程度。逐条标注与模块参考来源共同提供完整溯源。

### 10.3 速度

- 提交后 10 秒内出现第一个可用分析模块；
- 完整基线报告 P95 ≤60 秒；
- 每个模块完成后立即展示。

## 11. 信源策略

### 11.1 信源层级

按以下顺序优先选择：

1. 原始文件、一手声明和原始数据；
2. 政府、科研机构、权威组织和同行评审论文；
3. 有明确编辑责任的专业媒体；
4. 其他可用于理解观点分布的公开内容。

自媒体用于呈现观点样本，事实证据优先采用更高层级信源。

### 11.2 数量与独立性

- 配置在线搜索时，每次认知体检目标使用 3–5 个独立高质量信源；未配置时信源模块不生成外部来源；
- 多个转载同一材料的页面只算一个来源；
- 信源数量与质量均如实展示；
- 质量优先于数量。

### 11.3 专家冲突

第二视角 Agent 按证据质量综合专家结论：

- 信源层级；
- 引用是否完整；
- 引用是否真正支持对应表述；
- 信息时效；
- 专家置信度。

证据仍有分歧时，并列呈现各方依据和信息补充方向。

## 12. Agent 设计

### 12.1 用户可见角色

用户始终只面对一个第二视角 Agent。它承担：

- 理解用户目标；
- 管理连续对话；
- 决定分析顺序和工具调用；
- 调用内部专家 Agent；
- 综合并解释专家分歧；
- 修订报告；
- 提出思考问题。

用户可见内容包括工作状态、已持久化的安全专家摘要、报告和对话；内部工具名、模型内部推理、
原始提示词与原始模型输出不构成产品输出。

前台 Agent 保持冷静、客观、尊重用户判断的表达风格，使用描述性语言并把选择权交给用户。

### 12.2 内部专家

| 专家 Agent    | 核心职责               | 基线报告是否必调 |
| ----------- | ------------------ | -------- |
| 论证分析 Agent  | 主张、论据、假设、推理和结论     | 是        |
| 信源研究 Agent  | 检索、筛选、引用和证据对照      | 是        |
| 多视角挑战 Agent | 反方、遗漏角度、利益相关者和二次审校 | 是        |
| 风险审查 Agent  | 五类认知风险及其原文证据       | 是        |
| 思维反馈 Agent  | 回应有效性、五维反馈和画像证据    | 用户回应后    |

角色固定，调用时机由前台 Agent 决定；普通追问调用与问题相关的专家。

### 12.3 自主性边界

Agent 可以自主决定：

- 先分析什么；
- 是否需要联网检索；
- 调用哪个专家或工具；
- 向用户追问什么；
- 如何根据新证据修订报告。

应用层固定并强制执行：

- 用户身份与数据权限；
- 思维画像授权；
- 内容与工具安全限制；
- 报告最低结构；
- 引用与推演标注；
- 工具调用上限和超时；
- 删除与数据隔离；
- 运行可追溯性。

网页和用户素材作为待分析数据处理，Agent 指令优先级、工具权限和用户数据隔离始终由应用层维护。

### 12.4 技术框架

- 应用主干：Next.js、React、TypeScript；
- Agent 框架：成熟的 TypeScript AI Agent 框架；
- 前台编排：工具循环 Agent；
- 专家 Agent：由前台 Agent 作为内部工具调用；
- 模型策略：通过 OpenAI 兼容协议接入通用 LLM 服务，MVP 只启用一个高质量、支持工具调用和结构化输出的模型；
- 数据与认证：关系型数据库、用户名和密码认证。

运行时使用真实 OpenAI 兼容模型和 `DATABASE_URL`；配置 `TAVILY_API_KEY` 时启用在线搜索。自动测试以测试级预定义桩验证流程；真实 LLM 的动态输出以固定样本人工评估。

产品能力保持模型供应商中立。实施时使用 30 条固定样本，从兼容 OpenAI 协议的通用 LLM 服务中选择达到质量、延迟和成本要求的一个模型，运行期聚焦一套稳定模型配置。

## 13. 思考回应与思维画像

### 13.1 体检内容，观察思考过程

认知体检的对象是用户提交的内容。思维画像基于用户主动回应所展现的思考过程。

提交内容为用户回应提供上下文，思考回应构成画像评价的核心证据。

### 13.2 有效思考回应

一次有效回应必须：

- 针对 Agent 当前提出的问题；
- 表达判断或明确保留判断；
- 至少给出一条理由、证据、假设或不确定性说明。

系统按语义完整度判断回应质量，满足上述条件的回应进入长期画像。

### 13.3 五个固定维度

| 维度     | 观察内容                       |
| ------ | -------------------------- |
| 证据意识   | 是否区分主张与证据，并检查证据相关性、充分性和可信度 |
| 视角广度   | 是否考虑不同立场、利益相关者和解释路径        |
| 假设识别   | 是否发现论证依赖但未明说的前提            |
| 逻辑严谨   | 推理是否连贯，结论是否超出证据支持范围        |
| 接受不确定性 | 是否承认信息边界、表达置信程度并在证据不足时保留判断 |

评价规则对用户公开，并在不同观点之间保持一致。

### 13.4 呈现方式

每个维度显示：

- 表现稳定；
- 有所展现；
- 尚需更多证据。

同时展示趋势、对应回应片段和置信度，以观察性反馈呈现用户的思维变化。

当同一思考倾向在多次回应中反复出现时，系统在对应维度下给出附证据的趋势观察。

### 13.5 冷启动

- 每次有效回应立即提供本次五维反馈；
- 至少完成 3 份报告且提交 5 次有效回应后，才生成长期思维画像；
- 画像页面持续显示证据积累进度，达到门槛后形成长期趋势。

### 13.6 辅助行为

只有以下高意图行为可以辅助画像：

- 修改思考回应；
- 主动查看相反视角；
- 展开外部信源；
- 根据新证据修正原判断。

辅助行为用于增加证据或调整置信度，维度趋势由有效思考回应决定。

## 14. 数据与隐私

### 14.1 授权

思维画像使用独立授权：

- 首次启用前解释数据用途；
- 认知体检报告作为基础能力持续可用；
- 用户可随时撤回；
- 撤回后停止新增画像证据；
- 用户可调整进入画像的内容和回应范围。

### 14.2 保存策略

以下数据默认持续保存，直到用户主动删除：

- 提交的完整原文或解析正文；
- 认知体检报告；
- 报告修订记录；
- Agent 对话；
- 思考回应；
- 思维反馈和画像证据；
- 授权状态。

### 14.3 删除

- 删除单份历史时，同时删除原文、报告、修订、对话、回应和相关画像证据；
- 删除后基于剩余证据重新计算思维画像；
- 清空画像时删除全部画像证据，并保留用户选择继续保存的报告；
- 删除账号数据时执行完整级联删除。

### 14.4 数据安全

- 数据访问策略保证用户只能访问自己的数据；
- 密钥只存在于服务端环境；
- Agent 追踪记录工作空间与 Agent run 元数据，并保护完整原文、用户名和用户回应；
- 日志使用 `workspaceId`、`agentRunId` 和错误类型；
- 所有数据操作都先验证当前用户身份与资源归属。

## 15. 逻辑数据模型

| 对象     | 含义                | 主要关系           |
| ------ | ----------------- | -------------- |
| 用户     | 以用户名和密码注册的产品使用者 | 拥有工作空间、历史和授权   |
| 分析素材   | 用户粘贴或从链接解析出的内容    | 属于一个工作空间       |
| 工作空间   | 一次认知体检的持久化上下文      | 拥有报告、对话和 Agent run |
| Agent run | 工作空间内一次后台 Agent 执行  | 保存状态与安全专家摘要     |
| 认知体检报告 | 当前可见的结构化分析结果      | 拥有多个模块和修订记录    |
| 报告修订   | 某次对话导致的内容变化与理由    | 指向报告及触发它的对话    |
| 信源     | 外部检索结果及其元数据       | 被报告中的具体表述引用    |
| 思考回应   | 用户对思考问题的回应及其有效性状态 | 产生本次思维反馈       |
| 画像证据   | 回应片段或高意图辅助行为      | 支撑一个画像维度及置信度   |
| 思维画像   | 五个维度的长期趋势         | 由当前纳入范围的画像证据计算 |
| 授权记录   | 用户对画像数据使用的当前选择    | 控制画像证据的新增与删除   |

## 16. 功能需求

### 16.1 认证与历史

- **AUTH-01**：用户可以使用唯一用户名和密码注册、登录和退出。
- **AUTH-02**：用户名不可用、凭据错误和频繁请求必须得到安全引导，并保护账号状态隐私。
- **AUTH-03**：密码只以自适应哈希结果保存，认证会话支持过期和主动撤销。
- **HIST-01**：用户可以查看自己的认知体检历史。
- **HIST-02**：用户可以从历史报告继续对话。
- **HIST-03**：用户可以删除单份历史或全部账号数据。

### 16.2 输入

- **INPUT-01**：必须支持粘贴 1–20,000 个字符的文本。
- **INPUT-02**：支持中文、英文和中英混合素材。
- **INPUT-03**：可选支持普通文章和公众号链接。
- **INPUT-04**：链接需要补充正文时必须提供文字粘贴入口。
- **INPUT-05**：输入满足内容、长度和链接规则后创建工作空间。

### 16.3 Agent 与报告

- **AGENT-01**：用户只与第二视角 Agent 交互。
- **AGENT-02**：基线报告必须调用前四类专家。
- **AGENT-03**：专家先独立分析，再由前台 Agent 综合。
- **AGENT-04**：多视角挑战 Agent 必须二次审校综合草稿。
- **REPORT-01**：报告必须包含速览和五个固定模块。
- **REPORT-02**：每个关键表述必须标明原文提取、外部信源或 AI 推演，并显示置信度。
- **REPORT-03**：外部信源必须展示发布者、日期和链接。
- **REPORT-04**：认知风险必须附原文片段、解释和置信度。
- **REPORT-05**：专家结论存在证据分歧时必须并列展示。
- **REPORT-06**：首个模块 10 秒内可见，完整报告 P95 ≤60 秒。

### 16.4 对话与修订

- **CHAT-01**：用户可以针对报告中的具体内容发起质疑。
- **CHAT-02**：Agent 可以按需重新调用专家或工具。
- **CHAT-03**：报告修订必须展示变化位置、理由和新增证据。
- **CHAT-04**：网络重连后可以恢复已保存的工作空间与对话状态。

### 16.5 思维反馈

- **PROFILE-01**：系统按语义规则识别有效思考回应。
- **PROFILE-02**：有效回应必须获得本次五维反馈。
- **PROFILE-03**：至少 3 份报告和 5 次有效回应后才形成长期画像。
- **PROFILE-04**：画像以观察性反馈、趋势、证据和置信度呈现。
- **PROFILE-05**：画像趋势由有效思考回应决定，辅助行为用于调整置信度。
- **PROFILE-06**：画像授权生效后新增画像证据。

## 17. 状态、恢复与连续服务

### 17.1 工作空间与 Agent run 状态

- Agent run：排队、运行、已中止、可恢复、完成；
- 工作空间：等待、分析中、部分完成、已中止、已完成、待恢复。

每个报告模块独立记录状态。用户可终止最新运行，工作空间保留已完成模块和安全专家摘要；
“继续分析”创建新的 Agent run，只补齐未完成工作。

### 17.2 连续服务规则

| 运行状态     | 产品行为                 |
| -------- | -------------------- |
| 链接需要补充正文 | 提示用户粘贴正文，确认内容后创建工作空间 |
| 联网检索服务波动 | 继续内容分析，并展示信源模块状态     |
| 单个专家需要重试 | 展示已完成模块，并提供对应模块重试入口  |
| 二次审校进行中  | 保留草稿并展示审校进度          |
| 模型输出需要校正 | 自动重试一次，并展示模块处理状态     |
| 页面刷新或断线  | 从持久化工作空间恢复报告、摘要与对话    |
| 用户终止 Agent run | 保留已完成内容并提供“继续分析”       |
| 用户删除画像证据 | 重新计算剩余画像，并更新置信度      |

### 17.3 事实型内容

当素材主要是事实性描述、没有可识别的论证时：

- 将论证骨架标记为“当前内容以事实陈述为主”；
- 展示可识别的事实陈述；
- 信源研究仍可展示相关外部信息；
- Agent 可询问用户希望检查哪一项事实或从哪个角度继续。

## 18. 安全、合规与表达

### 18.1 内容边界

系统支持对政治、社会等争议议题进行中立结构分析。涉及违法活动、明确伤害指导、隐私泄露等高风险请求时，系统提供安全提示、合法替代信息和必要的访问限制。

### 18.2 表达规范

- 结论先行，模块化展示；
- 使用“原文主张”“该信源指出”“当前证据不足”等描述性语言；
- 采用尊重用户判断权的描述性表达；
- 关键不确定性必须显式呈现；
- 固定提示：“本报告由 AI 生成，旨在提供多角度思考框架。请核对引用，并结合自身知识独立判断。”

### 18.3 工具安全

- 网页内容作为分析数据处理，系统指令保持最高优先级；
- 搜索、抓取和数据库工具使用最小权限；
- Agent 在用户授权范围内使用数据；
- 工具调用设置次数、超时和内容大小上限；
- 外部链接在界面中清楚标识来源域名。

## 19. 非功能需求

### 19.1 性能

- 首个可用模块：≤10 秒；
- 完整基线报告：P95 ≤60 秒；
- 用户操作必须立即获得处理中、已完成或待恢复反馈。

### 19.2 可靠性

- 报告成功生成率 ≥90%；
- 模块独立运行并支持逐项恢复；
- 重试和继续沿用当前工作空间；
- 已完成模块和对话可在重连后恢复。

### 19.3 可访问性

- 所有核心操作可通过键盘完成；
- 状态、风险和置信度同时使用文字、图形和颜色表达；
- 流式更新通过合适的辅助技术提示，并保持焦点稳定；
- 图形化报告同时提供等价文本结构。

### 19.4 可观测性

监控：

- 首个模块耗时；
- 完整报告 P50/P95；
- 各专家成功率与耗时；
- 搜索、解析和模型工具恢复率；
- 降级报告比例；
- 单次 Agent run 的模型与搜索成本；
- 报告修订次数；
- 有效思考闭环率。

## 20. 评估与验收

### 20.1 Agent 固定样本

至少 30 条样本，覆盖：

- 五类认知风险；
- 单边论述；
- 纯事实内容；
- 外部证据互相冲突；
- 高质量信源不足；
- 边界输入；
- 提示注入式网页内容；
- 中英混合内容。

两名评审独立评价，分歧项由团队复核。

### 20.2 质量门槛

| 指标          | 门槛   |
| ----------- | ---- |
| 报告结构完整率     | ≥90% |
| 引用链接有效率     | ≥95% |
| 引用支持对应表述的比例 | ≥85% |
| 高置信度风险标注准确率 | ≥80% |
| 中立性人工通过率    | ≥85% |

### 20.3 核心验收场景

#### 场景 A：争议观点

- **Given** 用户提交“30 岁以后考公是获得稳定人生的唯一选择”。
- **When** 系统生成基线报告。
- **Then** 报告识别核心主张、相关论据、隐藏假设、其他视角、未知信息和可能的以偏概全，并将绝对化判断标记为原文观点。

#### 场景 B：信源冲突

- **Given** 用户提交一篇包含政策影响判断的评论文章。
- **When** 外部高质量信源对该判断存在分歧。
- **Then** 报告并列展示支持和质疑证据，注明来源与日期，把最终判断留给用户。

#### 场景 C：用户质疑报告

- **Given** 用户指出某项认知风险误读了原文。
- **When** 第二视角 Agent 复查原文和证据。
- **Then** Agent 回应异议；若修订报告，显示修改位置、理由和新增证据。

#### 场景 D：信源服务恢复

- **Given** 联网检索服务暂时受限。
- **When** 其他专家正常完成。
- **Then** 系统返回内容分析，并展示信源对照的当前状态和重试入口。

#### 场景 E：画像冷启动

- **Given** 用户只完成一份报告和一次有效回应。
- **When** 用户打开思维画像。
- **Then** 系统展示本次反馈和长期画像的证据积累进度。

#### 场景 F：删除画像证据

- **Given** 用户已形成长期画像。
- **When** 用户删除一份历史报告。
- **Then** 相关回应和画像证据同步删除，画像按剩余证据重新计算。

## 21. 数据埋点

只记录实现产品验证所需的事件：

- `analysis_submitted`：提交分析；
- `first_module_shown`：首个模块可见；
- `baseline_report_completed`：基线报告完成；
- `report_degraded`：报告发生降级及原因类型；
- `report_item_challenged`：用户质疑具体内容；
- `report_revised`：报告完成修订；
- `thought_response_submitted`：提交思考回应；
- `thought_response_accepted`：回应被判定有效；
- `profile_feedback_viewed`：查看本次或长期反馈；
- `report_helpfulness_rated`：报告有帮助/待改进。

埋点保存工作空间级事件元数据；进入思维画像的高意图行为由画像授权控制。

## 22. 上线、回退与部署

### 22.1 交付顺序

1. 本地跑通文本输入、基线报告、对话修订、思维反馈、历史与画像；
2. 通过 30 条固定样本质量门槛；
3. 完成至少 20 名目标用户的可用性验证；
4. 冻结功能，只修复阻断问题和质量回退；
5. 根据赛事提交要求完成部署。

里程碑统一以赛事提交节点为终点。

### 22.2 配置版本与回退

- Agent 指令、工具配置和模型配置必须有版本号；
- 新配置达到固定样本门槛后进入稳定版本；
- 上线后报告成功率低于 90% 时回退上一稳定配置；
- 单个专家或工具状态波动时启动模块恢复流程，产品持续提供其余能力。

### 22.3 部署原则

- 本地测试环境可独立运行；
- 应用遵循标准 Next.js Node.js/Serverless 运行方式；
- 产品内核保持运行环境中立；
- 最终按目标运行环境完成部署适配。

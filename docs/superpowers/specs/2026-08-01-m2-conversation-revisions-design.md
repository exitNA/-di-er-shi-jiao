# M2：边聊边拆与报告修订

## 目标

在既有基线报告上交付可恢复的持续质疑流程：用户可针对报告条目提出异议，第二视角 Agent 复核原文、既有证据及按需检索结果，保存回应并在必要时修订报告。

## 适用范围

- 支持主张、信源关系和认知风险等报告条目的定向质疑。
- 保存连续消息、当前报告版本和简明修订记录。
- 显示修订位置、理由和新增证据。
- 刷新、SSE 重连或轮询后恢复消息和修订状态。
- 记录 `report_item_challenged`、`report_revised`。

本阶段不实现思考回应有效性判定、本次五维反馈、长期画像或历史删除。

## 架构与数据

复用 `analysis_events` 的 job 级游标、现有 SSE/轮询、资源所有权校验、产品事件记录及基线专家适配器。M2 不复用已完成分析任务的状态机；质疑本身拥有独立持久化状态，原报告始终可读。

新增两类记录：

- `conversation_messages`：用户和 Agent 消息、定向条目、处理状态、客户端幂等键与创建时间。
- `report_revisions`：触发消息、报告版本区间、变化位置、理由、新证据和摘要。

所有目标使用 `ReportItemTarget = { moduleType, section, itemId }`。认知风险增加稳定 `id`，禁止用数组下标或 DOM 标识作为业务定位。报告修订以 `reports.current_version` 为比较并交换（CAS）条件：仅当当前版本仍等于复核开始时的版本才提交；冲突时保留消息为待恢复并重新基于最新快照执行。

## 工作流

1. 客户端从报告条目发起质疑，提交目标、问题与幂等键。
2. 服务端验证会话、来源、资源归属、输入与幂等键；事务保存用户消息和处理中状态，追加事件并派发修订任务。
3. 修订任务读取当前报告、材料和已保存的消息上下文；按目标调用必要的专家或搜索，再生成结构化回应及可选模块修订。
4. 同一事务保存 Agent 消息、模块变更、报告版本、修订记录与事件。复核失败只更新该消息状态，保留原报告和可重试入口。
5. 客户端收到事件后重新读取完整快照；恢复时以数据库快照为真相。

## API 与可观测性

- `POST /api/analyses/:jobId/challenges` 创建幂等质疑；客户端不传用户标识。
- `GET /api/analyses/:jobId` 的快照增加报告 ID、当前版本、消息和修订记录。
- 既有事件端点增加会话和修订变更事件，仍只传游标提示，客户端随后获取快照。
- `report_item_challenged` 以消息 ID 去重；`report_revised` 以修订 ID 去重。

日志仅记录安全元数据（任务、消息、修订、目标类型与状态），不得记录完整原文、消息内容、凭据或会话令牌。

## 界面与可访问性

报告条目使用具语义名称的质疑按钮，例如“质疑：某项认知风险”。报告页面内并列展示对话面板和简明修订记录，不建立独立页面或模态框。消息、处理中、完成和失败状态通过简短的 `aria-live="polite"` 通知；更新不自动夺取焦点或滚动阅读位置。修订通过文本化的位置、理由、新证据和可聚焦锚点呈现，不只依赖颜色。

## 验证

- 单元：目标契约、快照合并与处理状态。
- 集成：所有权、幂等、消息/修订/模块/事件原子提交、报告版本冲突。
- 组件：键盘发起质疑、处理中与重试、修订定位和焦点稳定。
- Playwright：产品场景 C——质疑风险误读，看到回应、修订位置、理由和新证据；刷新后仍可恢复。

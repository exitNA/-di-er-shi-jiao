# 交互式分析脑图设计

## 目标

将工作区右侧的长报告替换为可点击的分析脑图，使用户可直观看到分析结构，并让 Agent 在处理追问时理解用户当前的分析焦点和最近浏览脉络。

## 范围

- 右侧区域展示脑图，不再同时渲染完整报告卡片。
- 用户可以点击脑图节点；点击的节点成为当前焦点。
- 系统记录本次会话中最近浏览的 3–5 个不同节点。
- 焦点和浏览路径在脑图中可见，也随用户消息一并传递给 Agent。
- 用户未选择节点时仍能发送消息；Agent 收到完整分析上下文并自行决定如何响应或修订。

## 脑图结构与视觉

- 中心节点显示当前分析主题，内容来自工作区的材料预览。
- 六个一级节点对应现有模块：核心主张、论证骨架、多视角、信源、认知风险、思考对话。
- 每个一级节点显示最多五个可追问的分析条目；未完成模块显示状态节点。
- 当前焦点使用青绿色描边和“当前焦点”标签。
- 最近浏览的节点采用低对比度浅色背景，并显示浏览顺序；当前焦点不重复标记为浏览节点。
- 节点点击仅表达分析意图；拖拽、缩放和滚动不计入上下文。
- 视图使用 CSS 布局与原生按钮实现，桌面端展示分支结构，移动端按中心节点和分支纵向浏览；不引入图谱依赖。

## 交互与消息上下文

每条用户消息提交时携带：

- 原始材料；
- 当前完整分析快照（模块、修订与已有对话）；
- 用户输入文本；
- 可选当前焦点；
- 最近 3–5 个浏览节点及其简短摘要。

当前焦点仅是 Agent 的决策信号，不是权限边界。Agent 可依据完整上下文选择解释、进行全局复核，或通过受控工具修订合适的报告条目。

## 数据与服务端边界

- 用户消息的目标改为可选：无焦点消息代表“整份分析”上下文。
- 现有带目标的历史消息与修订保持兼容。
- Agent 运行上下文包含完整快照和交互语义；输入经过既有 schema 验证，浏览路径限长、节点必须能由当前快照解析。
- 报告修改继续只能通过既有受控工作区工具完成；Agent 不能直接写数据库或任意模块。

## 失败与空状态

- 脑图尚无完成模块时，保留模块状态节点并允许用户发送全局问题。
- 焦点节点在更新后消失时，移除该焦点并保留其余有效浏览历史。
- 无法提交、无法恢复运行或 Agent 未产生修订时，沿用现有明确状态提示；不会把浏览操作误报为修改。

## 验收

- 右侧区域不再显示完整报告卡片，展示可操作的分析脑图。
- 脑图节点可点击，焦点与浏览路径均有对应视觉标记。
- 未选择节点时发送按钮可用。
- Agent 接收到完整分析与交互上下文，且可自主决定处理范围。
- 有焦点和无焦点消息均通过权限、所有权和 schema 校验。
- 现有报告修订仍仅由受控工具写入，历史目标型对话与修订可正常显示。
